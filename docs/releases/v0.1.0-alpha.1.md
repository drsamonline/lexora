# LEXORA v0.1.0-alpha.1

**A working, installable build — for testing, not for production data.**

This is the first release of anything, and it is an **alpha** on purpose: every release
precondition is met except the one that matters most for a compression claim. Read
"What is not proven" before you put anything irreplaceable in it.

## What it does

- **Exact compression of text.** `decode(encode(C)) == C`, byte for byte, for every input —
  empty, binary, mixed script, 200 KB single lines. Enforced by a per-block SHA-256 and a
  round-trip gate that refuses to write an archive it cannot read back.
- **A real archive format.** `.lxz` v0, frozen by ADR-0007: 128-byte header, per-block index,
  hashed trailer. Two conformance vectors ship in `tests/vectors/`.
- **Two codecs.** `zstd` (default, 15.9 MiB/s, ratio 0.335 on real prose) and `ziptastic`
  (CHCE; 0.228 at 0.05–0.48 MiB/s, needs the external binary — optional).
- **A queryable archive.** `lexora db`: SQLite index over compressed payloads. Full-text plus
  metadata filters, versioning, delete, compaction. Measured on 19 books: payload 6.5 MB,
  index 7.6 % of text, query 0.34 s, retrieval 0.47 s.
- **Ingestion.** `.txt`, `.md`, `.csv`, and PDF text layers via `lexora[pdf]`; scanned PDFs via
  `lexora[ocr]` + the external `tesseract` binary.
- **A GUI.** `lexora-gui` → **Query archive…** — search, filter, preview. It shells out to the
  CLI rather than reimplementing anything (ADR-0011).
- **A language seam.** English ships as the first *plugin* (ADR-0022); a second language can be
  added without touching the canonicaliser.

**736 tests, 0 skipped.** CI green. `python3 scripts/linkcheck.py` clean.

## What is not proven — read this

- **The compression claim.** The honest statement is *"about 20 % smaller than `xz -9` on a
  text-heavy sample of Project Gutenberg"*, measured on 19 books (18.5 MiB) and a 3.9 MiB
  protocol-shaped run. The full protocol-scope run — 1.054 GiB, three splits, 3 reps, a second
  machine class, `xz` via the CLI — **has not been run**. It needs hours on a machine this
  project does not have yet. Until then, treat every ratio here as indicative.
- **OCR accuracy.** The OCR path is verified end to end on a real 99-page scan (99/99 pages,
  provenance recorded), but the tests use a **stub binary**: they prove the plumbing, not that
  Tesseract reads your document well. Nothing has been checked against a human transcript.
- **`.lxdb` does not exist.** The single-file database is designed (ADR-0013, Proposed) and
  deliberately not built until the benchmark closes. `lexora db` uses a directory of `.lxz`
  files plus a SQLite index — that works today and is what this release ships.
- **One language.** The seam is real; English is its only implementation. Hindi, Gujarati and
  Chinese are packages that do not exist yet.
- **No encryption.** ADR-0009 left the encryption profile Proposed.

## Install

```bash
pip install lexora-0.1.0a1-py3-none-any.whl          # core: zstd only
pip install "lexora-0.1.0a1-py3-none-any.whl[gui]"   # + desktop query window
pip install "lexora-0.1.0a1-py3-none-any.whl[pdf,ocr]"  # + PDF and scanned PDF
```

```bash
lexora doctor                      # is this install healthy?
lexora canon --in in.txt --out c.bin
lexora pack  --in c.bin --out a.lxz
lexora verify --in a.lxz
lexora unpack --in a.lxz --out back.txt
```

## Known limitations

- **`ziptastic` is an external binary**, not vendored. Without it, `--codec ziptastic` fails with
  a clear message rather than falling back. `doctor` reports whether it is present.
- **A `ppmd` codec was added and withdrawn in one day** — the Python PPMd library corrupts 3–8 %
  of real documents. It survives only as a benchmark baseline. See ADR-0021's withdrawal record.
- **The GUI is pinned to `pyside6<6.12`**: 6.12 aborts with a Bus error *after* the tests pass,
  at Qt teardown on a headless runner.
- **`--jobs` is slower**, not faster, on small-core machines (measured twice). Opt-in.
- **Windows is untested.** Linux is the only environment anything here has run on.
